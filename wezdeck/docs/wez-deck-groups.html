Wez Deck, groups

Sorting forty sessions without losing a Saturday

Groups are only worth having if putting a session in one costs about a second. If sorting feels like filing taxes, you will do it twice and then stop. So the whole design is about making the first sort fast, and every later change free.

Chapter 1

Three moments, three tools

Organising things happens in three very different moods, and one clumsy feature can't serve all of them.

The pile

Triage mode

You sit down once and sort thirteen unsorted sessions. One session at a time, one keypress each. Try it below.

The new arrival

Group on the way in

A session you launch from the deck asks for its group as part of its name, so it is never unsorted to begin with.

The odd one

Action strip

Shift plus a session's key opens a strip on that row: group it, pause it, or hand it over. Moving one session takes a second.

This is the real flow for Elephant's thirteen work sessions, using their actual names. Click the box to focus it, then press a number to put the session in that group, n to make a new group, ↵ to take the suggestion, s to skip, and z to undo. Or just click the chips.

Chapter 4

The rules underneath

Stored by session idA group follows the session through pause, resume and a WezTerm restart. Your tabs can be a mess and the groups still hold.
Groups are free to makeA group exists while it has a member. Empty groups disappear, so nothing needs cleaning up.
Renaming is one moveCtrl+R on a group header renames it everywhere, the same as renaming a project code.
No keystroke taxJumping is still the project code plus one key. Groups are for looking, folding and filtering, not for extra steps.
Ungrouped is allowedSingletons like 1032 can live in ungrouped forever. Triage never forces a group.
Windows are separateA group badge only offers a window at three tabs. The deck never creates or moves one on its own.
My leaning: build triage mode first. It is the one place where a thoughtless design makes people quit, and everything else (the strip, group-on-launch) is a small addition once the stored groups exist. The mouse should work too: dragging a row onto a group header does the same thing as a number key.

The only decision I need from you before building this is how many groups per project you expect. If it is "a handful", number keys 1 to 9 are plenty. If it could reach twenty, I would add a type-to-search box in triage mode as well. For Elephant I would guess six or seven, which fits.
