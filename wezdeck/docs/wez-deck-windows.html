Wez Deck, windows

One window per second layer

The tree has two layers that matter: the project, and then the folder inside it (managers or work). Your idea is that each second-layer node gets a WezTerm window. I like it, because it makes the macOS window switcher mean the same thing the deck's tree means. Here is what it does to your forty sessions.

Chapter 1

The rule, and what it costs

One window for every (project, folder) pair that has something in it. Empty folders get no window, so nothing sits there looking lonely. That is the whole rule. The only wrinkle is Elephant, which has thirteen work sessions and would turn one window into a tab bar you scroll with a sense of despair. So windows get a cap, and when a folder fills up it spills into work 2.

One piece of good news first. All five of your windows are exactly 161 by 45 cells. A session moved between them keeps its size, so nothing gets resized, which is the thing Claude hates. The deck would check that before every move and refuse if the sizes differed.

Chapter 3

Housekeeping sessions

You mentioned general housekeeping sessions: the ones that clean up disks, check backups, or do a chore that belongs to no project. They deserve a project of their own so they stop showing up as "unsorted". I would call it hk, give it no working folder match, and start its sessions in your home directory. In layout B they land in the small window, which is exactly the right amount of ceremony for a chore.

Two sessions are unsorted today: the chatgpt-export one and a plain ref-well-plate shell. The first looks like housekeeping to me. I would not move either without your say.

Chapter 4

A layer between project and session

You are right that it does not exist yet. Today the tree is project, then managers/ or work/, and work/ is one flat list. For Elephant that is thirteen sessions in a row, and the only structure is whatever you remember. The fix is a layer of groups inside a project: a handful of named streams of work that sessions belong to.

elp
managers/ · pr, dev, issue, instance, prod
mic/ · mic-import, mic-search
mainline/ · mainline-day, mainline-dawn
(ungrouped) · 9 more
Example only. The two groups shown are what a name-prefix guess finds in your Elephant sessions today. The other nine need you to say where they go.

How a session gets into a group. By hand, because you are happy to name things: in the panel you select a session and give it a group. The deck suggests a group from the name prefix (mic-, mainline-) and you accept or type your own. The choice is stored against the session's id, so it survives a pause, a resume and a WezTerm restart.

Keys stay short. Groups organise the tree and the filter but do not add a keystroke. Within a project every session still has one unique key, so elp then the key is still two presses. Typing a group name filters to it.

Windows. I would not give every group a window, or Elephant alone would spawn a dozen. A group earns its own window at three tabs, the same threshold as the small window above. Everything else stays in the project's work window.

My leaning: yes to groups, as organisation first and windows second. They cost one name per session and give you the structure you were missing, without touching a single running session.
Chapter 5

Pulling it together

The rule gives every session an address of three parts: project, folder, and a key. The window it lives in is just the second part made physical. Under B you would end up with seven windows, none overflowing, and the deck would know which one a new session belongs in without being told. Titling windows so Mission Control shows elp · managers instead of whichever session is active is a small extra I can add later.

Groups sit on top of this as the third layer of the tree and leave the window rule alone, except that a big group can pull itself out into a window.

Three things to settle: the tab cap per window (I assumed 7), the three-tab threshold for the small window, and the code for housekeeping. Say the word on each, or tell me to go with my defaults, and the deck can start placing new sessions by this rule.
