Wez Deck, revision two

The sidebar edition

You asked for a tree you can see all the time: repo or project at the top, managers underneath, and a short code for everything so you can jump without a mouse. Fair. A picker you open is a phone book; a sidebar is a map pinned to the wall.

Chapter 1

The map on the wall

Every repo or project gets a three-letter code you choose by hand. Under each one sit two folders: managers/ with a one-key shortcut per manager, and work/ with numbered sessions. Collapsed repos show a roll-up, so a closed folder still tells you when something inside needs you.

The sidebar below is live. Click it, then try typing gdt and then p. Press Space to jump to the next session that needs you. Press Esc to clear. Clicking rows and folding folders works too.

My leaning: with this structure, tags stop being the main way to organise things. Position in the tree does that job. Keep tags as an optional second axis, reached through a / filter at the top of the sidebar, and don't make yourself maintain them.
Chapter 2

Addresses, not searches

Because you are happy to name things by hand, every session gets a short path: gdt.p is the pr-manager in growth-detector, gdt.1 is its first work session. That is two or three keystrokes with no fuzzy matching to go wrong, which is what makes it feel like a cockpit instead of a search box.

/Filter by tag, state or name. The picker from revision one lives on here.

One assumption I made: some managers belong to a repo (a pr-manager for each) and some cut across everything (instance and prod). I gave the cross-cutting ones their own pseudo-project, ops, so they sit in the same tree instead of a special case. If every manager is really global, you would have one ops and the per-repo managers/ folders disappear.

Chapter 3

How a sidebar exists in a terminal that has none

Here is the awkward truth: WezTerm has no sidebar. What it has is panes, and a pane can run anything, including a small program that draws a tree. The question is how that pane follows you around. I see three ways.

B · Left pane in every tab

The honest, boring one

Each tab gets a 26-column pane on the left running the same tiny tree program. They all read one registry file and redraw when it changes.

  • Simple and robust, built from stock WezTerm
  • One small process per tab
  • A toggle key hides or shows all of them
C · One sidebar that follows you

The clever one

A single sidebar pane is moved into whichever tab you activate, using WezTerm's move-pane support.

  • One process, always in sync
  • Fiddly: a tab switch rearranges panes
  • I would not trust it until I had tried it
A · Overlay only

The tree as a popup

The same tree, but it appears on a hotkey and vanishes after you jump.

  • Costs no screen space
  • Not "always visible", so no roll-up glance
  • Good fallback, and nearly free once B exists
My leaning: build B, because it is the version that works on day one, then keep A as the same program launched in a floating pane. Try C only if running a sidebar in every tab turns out to bother you. With sessions as tabs, you can also hide WezTerm's own tab bar, since the sidebar replaces it.

The tree program itself can be small: a Python script using curses (or Textual if you want mouse support), a couple of hundred lines. It reads the registry, watches for changes, and calls wezterm cli activate-pane when you pick something.

Chapter 4

What changes in the plan

Less than you might fear. The registry, the hooks that set state, the context meter, and the relay from revision one all stay. The change is that slice 0 becomes "registry with codes and shortcuts, plus the sidebar program" instead of "picker first". The picker becomes the / filter inside the sidebar, which makes it a feature of the sidebar rather than a separate thing to build.

Which brings us back to the one decision that shapes everything else: whether managers live under each repo, under a shared ops, or both. Tell me which is closer to how your managers really work and the codes you want for your repos, and I will build the registry and sidebar against your actual setup instead of my invented one.
